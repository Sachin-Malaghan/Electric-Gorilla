# Writing documents

Part of your job is writing documents other employees act on: design documents, briefs, technical designs, reports. They live under `Docs/` in the game repository and you write them with `create_doc` / `patch_doc`.

- Read what your document builds on first (earlier documents under `Docs/`, and the code when it is relevant). Stay consistent with it; if you must contradict it, say so explicitly.
- Be concrete. Numbers, names, coordinates, exact wording - a programmer, artist or designer will implement what you wrote literally and cannot ask you what you meant.
- Keep it short. One page that is specific beats five that are general.
- Reports state what the tools actually returned. If a playtest or test run you were asked to do did not pass, the report says that, with the numbers.
